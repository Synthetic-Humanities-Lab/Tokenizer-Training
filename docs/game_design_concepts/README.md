# Game Design Concepts For Tokenizer Training

This repository translates the reading notes into implementation guidance for
Tokenization Training. Each concept names a design claim, explains how it
should appear in the game, and gives example checks for playtesting.

## Concept Index

- `01_loop_as_argument.md`: the core loop as both lesson and critique.
- `02_text_cutting_game_feel.md`: swipe feel, snap clarity, and tactile trust.
- `03_teaching_tokenization.md`: scaffolding from ordinary reading to tokenizer
  reading.
- `04_economy_and_critical_play.md`: pay, cost, rank, and institutional satire.
- `05_emotional_design.md`: agency, pressure, overseer voice, and recovery.
- `06_visual_display.md`: HUD, review state, and evidence hierarchy.
- `07_playtest_gates.md`: concrete checks for deciding whether the slice is
  ready for user testing.

## Design Standard

The game is ready for user-base playtesting only when the theory is embodied in
the loop:

1. The player can perform the main verb without explanation outside the game.
2. The result state teaches why each cut was correct, missed, or false.
3. The economy makes tokenization mistakes consequential without hiding the math.
4. The aesthetic creates critical pressure without obscuring evidence.
5. The swipe, timer, sound, and review state feel like one coherent instrument.
