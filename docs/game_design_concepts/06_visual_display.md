# Concept 06 - Visual Display

Draws on: Tufte graphical excellence, graphical integrity, data-ink, density,
and multifunctioning marks.

## Design Claim

The interface must look like worn enterprise software while behaving like a
precise evidence display. Degraded style is acceptable; degraded readability is
not.

## Implementation Guidance

- Put prediction evidence near the text: possible cut guides, staged cuts, and resolved
  cut labels.
- During review, use the feedback card for visible token, Token Credit, and cut-audit
  evidence. Keep its generated technical descriptor hidden rather than adding a
  second explanation surface.
- Keep the mobile HUD to `CREDITS`, `TIME`, `BEST RUN`, and `CURRENT`; the browser
  may retain verified/rework and progress fields when space supports them.
- Use low-contrast background grids and chrome.
- Avoid decorative elements that compete with boundary positions.
- Keep the control row in `Sound`, `Clear`, `Exit`, `Resolve` order.
- Keep typography stable and readable across portrait and desktop viewports.

## Example In-Game Expression

- Correct, missed, and false cut markers use position, color, and label together.
- One feedback card appears during review; no separate token strip competes with
  it or Wiener speech.
- The timer bar supports urgency without hiding the sentence.

## Playtest Questions

- Can players read the text and markers on mobile?
- Can players compare their cuts to truth without scanning the whole screen?
- Does any aesthetic chrome obscure data?
